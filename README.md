# Паспорт доступности ОСИ — БОЙКОВГРУПП

Самостоятельное приложение React + Vite + TypeScript с серверным рендерингом. Backend: Node.js + Express + SQLite. Главная, страницы акта обследования, анкеты и актуализации паспорта ОСИ, шесть шагов экспресс-проверки, контактная форма и юридические страницы перенесены из утверждённой версии сайта, включая последние правки hero и фотографий. В админке доступны защищённый просмотр заявок, настройки лимитов вложений и управление статьями. Контент, цены и SEO находятся в исходниках проекта.

## Быстрый запуск в Windows / PowerShell

Нужны Node.js 24.15 или новее в ветке 24.x, npm и Git для загрузки на GitHub. Дополнительная установка SQLite не нужна: используется встроенный модуль Node.js. В Node 24 этот модуль имеет статус release candidate и может выводить соответствующее предупреждение.

Откройте корень распакованного проекта в WebStorm, затем выполните:

```powershell
npm ci
Copy-Item .env.example .env
npm run dev
```

Команду копирования выполняют один раз, когда своего .env ещё нет. Не заменяйте существующий .env этим шаблоном. Сервер доступен по адресу, который напечатан в терминале; по умолчанию это http://localhost:5173/. Внешний вид и коммерческие тексты сохранены.

Для просмотра заявок отдельно выполните npm run admin:setup и перезапустите сервер. Команда генерирует пароль админки, выводит его только в ваш терминал и записывает хеш пароля с секретом сессий в .env. Сохраните пароль в своём менеджере паролей. Скрипт не заменяет уже настроенные учётные данные. Панель заявок открывается по адресу /admin/. Главная страница и её SEO доступны и без настройки входа в админку.

Для уже настроенной админки используйте `npm run admin:migrate`: ввод текущего пароля скрыт, пароль сохраняется, SHA-256 в `.env` заменяется на scrypt. После миграции перезапустите Node.js или пересоздайте Docker-контейнер с новым окружением. Старые cookies после обновления не принимаются — войдите заново. Явная смена пароля: `npm run admin:rotate-password`. Порядок обновления и отзыв сессий описаны в [docs/ADMIN-AUTH.md](docs/ADMIN-AUTH.md).

База data/site.sqlite и её таблицы создаются автоматически при первом запуске. Файлы базы, пароли, зависимости и сборка исключены из Git. Запуск приложения, в отличие от загрузки исходников на GitHub, требует работающего Node.js-сервера.

## Если dev-сервер постоянно перезапускается

В текущей версии npm run dev запускает сервер без общего Node --watch. Интерфейс и CSS продолжают обновляться через Vite HMR. После изменения файлов server/ или настроек .env остановите процесс сочетанием Ctrl+C и запустите npm run dev снова.

В раннем архиве dev-команда содержала --watch. Этот режим отслеживал импорт временного конфига Vite из node_modules/.vite-temp, который Vite удаляет после загрузки. Из-за этого сервер попадал в цикл перезапуска. Для исправления существующей распакованной копии не требуется заменять .env или базу — достаточно изменить dev-команду в package.json.

Предупреждение ExperimentalWarning про SQLite само по себе не завершает сервер и не требует удаления базы. Успешный запуск заканчивается строкой Server ready at с адресом приложения.

## SEO и маршруты

Сервер отдаёт готовый HTML для всех страниц. Поисковому роботу не нужно выполнять JavaScript, чтобы прочитать заголовки, основной текст, FAQ, цены и ссылки. React затем подключает интерактивные формы и навигацию к этому же HTML.

Сохранены:

- один H1, иерархия заголовков и все 17 смысловых блоков;
- title, description, canonical, Open Graph и изображения OG;
- JSON-LD Organization, Service/Offer и FAQPage;
- отдельные адреса /privacy/ и /personal-data/;
- динамические /robots.txt и /sitemap.xml;
- noindex для админки, юридических страниц и страницы 404;
- настоящий HTTP 404 для отсутствующих адресов и ресурсов;
- перенаправление известных адресов на вариант с завершающим слешем;
- подписи изображений, локальные ресурсы и preload шрифта.

Дополнительно добавлены Twitter Card и кеширование файлов с хешем в имени. Главная открыта для индексации по умолчанию: сервер выдаёт meta robots index, follow и Allow: / в robots.txt. Canonical, Open Graph, JSON-LD и sitemap.xml формируются на сервере. Отдельного переключателя SEO в админке больше нет.

Публичные URL с параметрами доступны для обхода: UTM и выбор услуги/объекта не входят в canonical, страницы пагинации блога имеют собственный canonical, поиск и категории блога сохраняют noindex. Префиксы `/admin` и `/api` закрыты независимо от query. Подробная политика и примеры: [docs/ROBOTS-PARAMETERS.md](docs/ROBOTS-PARAMETERS.md).

Контент главной, общий каталог услуг и цен, контакты и вопросы берутся из src/content/home.json. Тексты страницы /akt-obsledovaniya-osi/ — из src/content/survey.json. Цены акта подставляются из общего каталога во все коммерческие блоки, FAQ, SEO и schema.org. Тексты юридических страниц — из src/content/legal.json. После изменения этих файлов production-версию нужно пересобрать и перезапустить. Проверка структуры выполняется при запуске и при npm run check.

Старые сохранённые записи content_entries, если они остались в SQLite после прежней версии, больше не читаются. В частности, прежнее значение indexing=false не может закрыть главную от поиска. API редактирования контента удалён. Уже сохранённые заявки продолжают читаться из существующей базы.

Технический перенос сохраняет доступность контента для поиска; позиции и фактическая индексация зависят также от домена, доступности сайта и работы поисковых систем.

## Формы и панель заявок

Чтение статей разделено на полные записи и краткие карточки: до 12 в существующем блоге, до 25 в админке, до трёх связанных материалов. Поиск охватывает весь доступный каталог; sitemap читает только slug. Навигация, SEO, ограничения и совместимость описаны в [docs/ARTICLE-READS.md](docs/ARTICLE-READS.md).

Неожиданные отказы обработки заявок создают безопасные JSON-события с кодом причины, счётчиками и случайным `X-Incident-ID` для связи с ответом сервера. Контакты и содержимое документов в журнал не попадают. Чтение событий и границы мониторинга описаны в [docs/DIAGNOSTICS.md](docs/DIAGNOSTICS.md).

Запросы админки ограничены одним дедлайном на соединение и чтение ответа: 30 секунд для JSON, 120 секунд для изображения, 15 секунд для хранилища. После ошибки ожидание завершается; изменяющие запросы автоматически не повторяются. Работа с неподтверждённым результатом и сохранением данных описана в [docs/ADMIN-REQUESTS.md](docs/ADMIN-REQUESTS.md).

В админке доступен блок «Хранилище файлов»: объём и остаток квот, предупреждение от 80% и предпросмотр ручной очистки неиспользуемых изображений. Защита статей и черновиков, ограничение по возрасту и порядок резервирования описаны в [docs/STORAGE.md](docs/STORAGE.md).

Сохранены пять вопросов и контактный шаг, возврат назад, выбранные ответы, множественный выбор по конфигурации и выбор объекта из карточек. Первичная классификация не добавляет сопровождение согласования к комплекту документов автоматически.

Заявка записывается в SQLite вместе с контактами, исходными вопросами и ответами, услугой, UTM, датой, UUID и согласием. Одинаковые повторы не создают дубликат, изменённый запрос с тем же UUID получает 409. Успех показывается после подтверждённого сохранения; ошибка сохраняет введённые данные в форме.

Ожидание ответа ограничено 30 секундами без вложений и 120 секундами с документами, включая чтение ответа. После ошибки можно повторить неизменённую заявку с тем же requestId; успех требует подтверждения именно этого ID. Подробности и границы сохранения черновика описаны в [docs/LEAD-SUBMISSION.md](docs/LEAD-SUBMISSION.md).

UTM сохраняются при загрузке публичной страницы в sessionStorage текущей вкладки и используются формами и событиями после внутренних переходов. Новый непустой набор меток целиком заменяет предыдущий; внутренние ссылки не дополняются UTM. Правила и ограничения описаны в [docs/ATTRIBUTION.md](docs/ATTRIBUTION.md).

В админке доступны вход, просмотр заявок, настройки лимитов вложений, раздел статей и выход. Разделы «Блоки страницы», «Услуги и цены», «Экспресс-проверка», «Контакты и настройки» и «SEO» удалены. Данные заявок доступны только после входа. Cookie сессии HttpOnly и SameSite=Strict; для HTTPS применяется Secure. Пароль и секрет сессий задаются только на сервере.

Пароль проверяется через scrypt с индивидуальной солью. Сессии хранятся в SQLite; исходный секрет токена в базе не сохраняется. Выход отзывает текущую сессию и все копии её cookie. Изменение настроенного хеша пароля или секрета при перезапуске отзывает все сессии. Срок сессии остаётся восемь часов.

Список заявок показывает по 25 записей с переходами «Назад» и «Далее», общим количеством и обновлением с возвратом к новым заявкам. Доступна вся сохранённая история, включая записи за пределами первых 100. Правила пагинации и проверки описаны в [docs/LEAD-HISTORY.md](docs/LEAD-HISTORY.md).

Почта и CRM не подключены: получатель пока не задан. Заявки сохраняются в SQLite и просматриваются в /admin/. Данные и секреты ранее размещённого сайта в архив не включены.

Ценовые маркеры {{price:passport}}, {{price:survey}}, {{price:questionnaire}}, {{price:support}}, {{price:full}} и {{relatedDocumentPrices}} продолжают работать.

## Проверки и production-сборка

Правила разработки и ревью описаны в [CODESTYLE.md](CODESTYLE.md). Для воспроизводимой среды используйте версию Node.js из `.nvmrc` и установку `npm ci`.

```powershell
npm run check
```

Quality Gate проверяет форматирование Prettier, ESLint без предупреждений, dependency audit с блокировкой high/critical, strict TypeScript, production-сборку клиента и сервера, затем запускает все тесты последовательно. Команда не изменяет исходники. Интеграционные проверки поднимают настоящую production-сборку на временном локальном порту и используют отдельную временную базу, которую удаляют после завершения.

Для автоматического форматирования используйте `npm run format`, для локальных исправлений ESLint — `npm run lint:fix`, затем просмотрите diff и повторите `npm run check`. Проверки без исправления доступны отдельно: `npm run format:check`, `npm run lint`, `npm run audit:check`, `npm run typecheck`.

Для dependency audit нужен доступ к npm registry. Умеренные предупреждения отображаются, но не блокируют gate; текущие версии и оставшиеся ограничения описаны в [docs/DEPENDENCIES.md](docs/DEPENDENCIES.md). Ошибка сети не считается успешным аудитом.

Workflow `.github/workflows/quality-gate.yml` выполняет ту же проверку на Linux и Windows для pull request и push в `main`. Чтобы запретить merge при неудаче, назначьте оба задания Quality Gate обязательными в настройках защиты `main` после первого запуска workflow. Сам файл workflow защиту ветки не включает.

Проверяются SSR-контент без клиентских скриптов, SEO и schema.org, canonical, статусы страниц, защищённый доступ к заявкам, проверка отправки, защита от повторов, сохранение заявок после перезапуска и экранирование JSON. Дополнительно проверено, что главная открыта для индексации без настройки админки и игнорирует старые настройки CMS в базе.

Чтобы запустить уже собранную версию:

1. Укажите точный публичный origin в APP_ORIGIN в .env.
2. Настройте HOST и PORT для своей площадки.
3. Выполните npm start из корня проекта.

```powershell
npm run build
npm start
```

Результат состоит из dist/client и dist/server. Для работы нужны обе части и production-зависимости из package-lock.json. Vite dev server и vite preview не заменяют production-сервер приложения. GitHub Pages не исполняет API и SSR этого проекта.

## Размещение на VPS

Настройте HTTPS через nginx или другой reverse proxy перед Node.js. В APP_ORIGIN укажите реальный HTTPS-origin без пути. Поддерживайте процесс через systemd, Docker или менеджер процессов, подходящий вашей площадке.

Перед открытием базы приложение проверяет согласованность публичного `APP_ORIGIN`, `site.domain` и корневого `seo.canonical`. Ошибка настройки останавливает запуск; адреса с путём, параметрами или учётными данными не обрезаются молча. Локальные origin поддерживаются отдельно и не заменяют публичные SEO-адреса. Правила и порядок смены домена: [docs/DOMAIN-CONFIG.md](docs/DOMAIN-CONFIG.md).

Параметры:

| Переменная            | Значение                                                         |
| --------------------- | ---------------------------------------------------------------- |
| APP_ORIGIN            | Точный origin публичного сайта; обязателен при npm start         |
| HOST                  | Адрес прослушивания, по умолчанию 127.0.0.1                      |
| PORT                  | Порт приложения, по умолчанию 5173                               |
| DATABASE_PATH         | Путь постоянной SQLite-базы                                      |
| TRUST_PROXY           | Число доверенных reverse proxy перед приложением; по умолчанию 0 |
| ADMIN_PASSWORD_SCRYPT | scrypt-хеш; создаётся через admin:setup или admin:migrate        |
| ADMIN_PASSWORD_SHA256 | Старый хеш; совместим до миграции через admin:migrate            |
| ADMIN_SESSION_SECRET  | Секрет HMAC сессий не короче 32 символов                         |

TRUST_PROXY=1 используется только за одним доверенным proxy, когда прямой доступ к Node.js извне закрыт. При прямом доступе оставьте 0: переданный посетителем X-Forwarded-For не используется для обхода ограничения частоты запросов.

SQLite рассчитана здесь на один экземпляр приложения с постоянным диском. Для согласованной копии работающей базы используйте `npm run db:backup`; проверка и восстановление доступны через `db:verify` и `db:restore`. Вложения, статьи и изображения входят в копию. Restore создаёт только новый каталог и не заменяет действующую базу. Полный порядок работы, Docker-скрипт и ежедневный systemd-таймер описаны в [docs/DATABASE-RECOVERY.md](docs/DATABASE-RECOVERY.md). Несколько контейнеров с независимыми файловыми системами потребуют другой схемы хранения.

В проекте есть необязательные Dockerfile и compose.yaml. Контейнер публикует приложение только на локальном порту VPS 8088; HTTPS настраивается отдельно. Данные хранятся в именованном томе passport-data. Заполните .env перед запуском docker compose up -d --build. Сборка и Node.js-проверки выполнены; Docker в среде подготовки не запускался.

Проверка `/healthz` возвращает 200 при доступности схемы и чтения SQLite, иначе 503. Команда `npm run healthcheck -- --origin http://127.0.0.1:5173` дополнительно проверяет серверный HTML главной. Этот же сценарий используется HEALTHCHECK в Docker. Для выкладки с ожиданием готовности используйте `docker compose up -d --build --wait --wait-timeout 120`. Поведение и ограничения описаны в [docs/HEALTHCHECK.md](docs/HEALTHCHECK.md).

`CONTAINER_DATABASE_PATH` задаёт путь SQLite внутри Docker volume, по умолчанию `/app/data/site.sqlite`; локальный `DATABASE_PATH` используется при запуске без Docker. После восстановления в новый каталог измените только контейнерный путь по инструкции и пересоздайте контейнер.

## Перед открытым запуском

Индексация главной уже включена. Домен и canonical заданы в src/content/home.json как https://pasport-dostupnosty.ru/ по ТЗ. Если выбран другой домен, измените site.domain и seo.canonical в этом файле, а также APP_ORIGIN в .env. Контакты, ID Метрики и юридические документы меняются в исходниках. При необходимости подключите выбранный канал доставки заявок и проверьте их просмотр в админке.

Страница акта обследования ОСИ опубликована в коде по адресу /akt-obsledovaniya-osi/; описание реализации находится в docs/SURVEY-PAGE.md. Отдельные отраслевые страницы пока не созданы. Блог /blog/ наполняется через раздел «Статьи» в админке; в поставке нет демонстрационных публикаций. Пустые внутренние ссылки не публикуются; карточки объектов открывают общую экспресс-проверку с выбранным типом. Контент следует предоставленным ТЗ.

## Анкета ОСИ

Коммерческая страница /anketa-osi/ использует общий компонент DocumentServicePage, контент src/content/questionnaire.json и цены из общего каталога. Заголовки карточек анкеты на главной и в сравнении документов страницы акта ведут на новую страницу. Квиз и форма получают questionnaire по умолчанию; посетитель может изменить выбранный документ. CMS-редактор не создавался. Подробности: docs/QUESTIONNAIRE-PAGE.md.

## Актуализация паспорта ОСИ

Страница /aktualizaciya-pasporta-dostupnosti/ имеет собственную композицию и тип цены «По согласованию». Общий квиз использует тематические вопросы. Контактная форма принимает прежние документы, сохраняемые в закрытой базе и доступные сотруднику после входа. Лимиты меняются в панели заявок. Публичный production требует HTTPS. Подробности реализации, миграции и ограничений: docs/UPDATE-PAGE.md.

## Редактор статей

После входа в /admin/ откройте «Статьи» → «Создать статью». Доступны черновики, автосохранение новой статьи, SEO, категории, обложка 16:9, форматирование, таблицы, ссылки, изображения и предпросмотр. Опубликованные статьи доступны по /blog/{slug}/ и появляются без пересборки. Весь текст отдаётся через SSR. Раздел редактирования страниц услуг не возвращался. Подробная инструкция и ограничения: docs/ARTICLES-ADMIN.md.

В обновлении редактора статей добавлены зависимости: после копирования файлов выполните npm ci. База автоматически обновится до схемы 3 с сохранением прежних данных. Перед обновлением остановите сервер и сохраните резервную копию data.

## Палитра

Текущая палитра: графит, нейтральные серые поверхности и оранжевые акценты. Общие цветовые переменные находятся в начале src/styles/globals.css; стили страниц используют эти переменные. На светлом фоне основные кнопки графитовые, на тёмном — светлые. Подробности и значения цветов: docs/PALETTE.md. Эта визуальная правка не добавляет зависимостей или миграций базы.
