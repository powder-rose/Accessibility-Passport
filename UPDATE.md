# Обновление существующего проекта

Последнее обновление: портрету в первом экране анкеты добавлено пространство. Рамка расширена до 370 px, сверху и по бокам добавлены отступы; снимок вписывается целиком, без увеличения и обрезки краями. Подпись выровнена по новым отступам. На телефоне сохранена горизонтальная карточка с дополнительным воздухом вокруг лица. Тексты, цена, маршруты, действия и файл фотографии сохранены.

Контрастная палитра «графит / нейтральный серый / оранжевый» и все предыдущие изменения включены. Бирюзовые и мятные фоны, линии, кнопки и иллюстрации заменены на нейтральные; на тёмных блоках используются светлые кнопки. Обновлены favicon и изображение для социальных сетей. Палитра применяется ко всем страницам, формам, блогу и админке. Описание: docs/PALETTE.md. Новых зависимостей и миграций относительно предыдущего архива с редактором статей нет.

Раздел «Статьи» и все предыдущие изменения включены: черновики, SEO, изображения, таблицы, ссылки, обрезка обложки и предпросмотр. Публичный блог — /blog/, статьи — /blog/{slug}/.

Новая страница: /aktualizaciya-pasporta-dostupnosti/. Переход с главной — в блоке дополнительных услуг. Архив содержит весь проект со всеми предыдущими правками.

Остановите npm run dev сочетанием Ctrl+C. Если запущен production-сервер, остановите и его. Распакуйте новый архив в отдельную папку. Откройте PowerShell в корне текущего проекта, где находятся package.json и .env.

Выполните, заменив путь к новой распакованной папке своим:

```powershell
& {
    $ErrorActionPreference = 'Stop'
    & "C:\Путь\к\распакованному\pasport-dostupnosti-react\apply-update.ps1" -ProjectPath (Get-Location).Path
    npm ci
    if ($LASTEXITCODE -ne 0) { throw 'npm ci failed. Server was not started.' }
    npm run dev
}
```

Скрипт проверяет название проекта и комплект файлов до копирования. Затем сохраняет заменяемые исходники и стандартный каталог data в .update-backups/palette-ДАТА, копирует полный комплект исходников и ресурсов, удаляет устаревшие редакторы и проверяет SHA-256 каждого скопированного файла. .env и рабочий каталог data не заменяются. Коммит и push не выполняются. Команда npm ci установит зависимости полного проекта, включая редактор статей из предыдущего обновления.

Важно: при первом запуске новая версия автоматически переводит базу на схему 3, добавляя статьи, историю URL и изображения; миграция также включает прежние закрытые вложения и лимиты. Прежние заявки сохраняются. Если DATABASE_PATH указывает вне каталога data, отдельно скопируйте эту базу и существующие файлы -wal/-shm после остановки сервера. Для отката нужны старые исходники и база до миграции; предыдущий сервер не поддерживает схему 3.

В Windows скрипт проверяет доступность файлов стандартного data для исключительного открытия. Это дополнительная проверка; приложение всё равно необходимо остановить перед копированием. В Linux проверка файловых дескрипторов не заменяет остановку процесса. Не запускайте сервер параллельно с обновлением.

Проверка использует доступ только на чтение: право записи не требуется для резервного копирования. При отказе выводятся полный путь и исходная причина. Ошибки совместного доступа Windows (32/33) выделены отдельно; запрет чтения не выдаётся за занятый файл. Защита от копирования файлов, занятых приложением, сохранена.

Если получено сообщение `Data file is in use`:

1. В терминале, где запущен сервер этого проекта, нажмите Ctrl+C. Если приложение запущено из WebStorm Run/Debug, нажмите Stop в соответствующей конфигурации.
2. Если SQLite открыта в панели Database WebStorm, отключите соединение. Закройте другие просмотрщики этой базы.
3. Повторите блок обновления выше. Удалять data, базу, -wal или -shm для снятия блокировки не нужно.

Если site.sqlite остаётся занятой, найдите владельца именно этого файла через встроенный «Монитор ресурсов» Windows:

```powershell
resmon.exe
```

Откройте вкладку «ЦП» → «Связанные дескрипторы» и в поиске введите site.sqlite. В результатах сверяйте полный путь с data/site.sqlite вашего проекта: одноимённая база может быть у другого приложения. Столбцы «Образ» и PID покажут процесс. Остановите его через соответствующий терминал/Run либо отключите соединение в найденном просмотрщике базы; затем повторите обновление. Эта команда только открывает диагностическое окно и не завершает процессы.

Описание поиска по связанным дескрипторам: [ответ Microsoft Support](https://learn.microsoft.com/en-us/answers/questions/4103433/how-to-fix-issue-with-shared-folder-not-opening-fi).

Если терминал запуска потерян, следующие команды только показывают Node-процесс, слушающий порт проекта. Они читают PORT из текущей .env либо используют 5173 и ничего не останавливают:

```powershell
& {
    $ErrorActionPreference = 'Stop'
    $projectPort = 5173
    if (Test-Path -LiteralPath '.env' -PathType Leaf) {
        foreach ($envLine in (Get-Content -LiteralPath '.env')) {
            if ($envLine -match '^\s*PORT\s*=\s*["'']?(\d+)["'']?\s*(?:#.*)?$') {
                $projectPort = [int]$Matches[1]
            }
        }
    }
    $listeners = @(Get-NetTCPConnection -State Listen -ErrorAction Stop |
        Where-Object { $_.LocalPort -eq $projectPort } |
        Select-Object -ExpandProperty OwningProcess -Unique)
    if ($listeners.Count -eq 0) {
        Write-Host "No listener on port $projectPort. Check SQLite viewers and the file path in the error."
    }
    foreach ($listenerId in $listeners) {
        Get-CimInstance Win32_Process -Filter "ProcessId = $listenerId" |
            Select-Object ProcessId, Name, CommandLine |
            Format-List
    }
}
```

Порт помогает найти сервер, но не доказывает, что файл заблокирован именно им: файл может удерживать IDE или просмотрщик SQLite. Если сервер запускался с другим PORT из окружения либо с --port, используйте его фактический порт для диагностики. Процессы других Node-проектов завершать не требуется.

Для production после копирования выполните npm run check и npm start с прежними настройками окружения. Публичный APP_ORIGIN должен использовать HTTPS. Для локальной проверки HTTP разрешён на localhost/127.0.0.1. Обновление только фронтенда недостаточно: сервер принимает файлы, хранит их и выдаёт после авторизации.

В новой странице сохранены тексты ТЗ, стоимость «По согласованию», шесть этапов, тематический квиз и 16 FAQ. Формы используют существующий механизм заявок. Файлы PDF, DOCX, XLSX, JPG и PNG связываются с заявкой; лимиты доступны в /admin/ → «Лимиты вложений». Редактор страницы не создавался.

Контент и SEO находятся в исходниках. Для Метрики нужно заполнить настоящий site.metrikaId в src/content/home.json. Канал email/CRM по-прежнему не подключён: заявки просматриваются в /admin/.

Чтобы отменить обновление, остановите сервер, восстановите исходники из указанной резервной папки и восстановите каталог data из её копии. При нестандартном DATABASE_PATH используйте собственную резервную копию этой базы. Если после обновления уже поступали новые заявки, сначала сохраните актуальную базу отдельно: возврат старой копии не включает эти новые записи.

Вход в раздел: /admin/ → «Статьи» → «Создать статью». Полное описание: docs/ARTICLES-ADMIN.md. Существующие пароль и настройки входа сохраняются. Для новой копии при необходимости используйте npm run admin:setup и перезапустите сервер. После публикации статья сразу доступна на сайте; отдельная пересборка для каждой статьи не требуется.
