# Заявки и посещаемость

Всё находится на существующей странице `/admin/`: новые публичные страницы не добавляются. После входа доступны сводка за 7, 30 или 90 календарных дней, график, таблица по дням, популярные страницы, источники переходов и история обращений.

## Заявки

Сводка считает всю базу, независимо от открытой страницы истории: все заявки за всё время, заявки сегодня и за выбранный период, распределение между формой обращения и экспресс-проверкой. Счётчики не зависят от ограничения списка в 25 записей.

В истории вместо JSON показаны дата по Москве, имя, телефон и форма. Раскрытая запись содержит контакты, услугу, тип объекта, комментарий, заполненные ответы проверки и ссылки на вложения. Пустые вопросы и технические поля отправки не выводятся. Данные и скачивание файлов доступны только авторизованному администратору.

## Как считается посещаемость

- Просмотр — событие после загрузки JavaScript на существующей публичной странице. Обновление страницы и возврат через браузерный back/forward cache создают новый просмотр. События имеют UUID, повтор одного события не увеличивает счётчик.
- Визит — сеанс с анонимным случайным токеном в `sessionStorage`. После 30 минут бездействия начинается новый визит. Сервер дополнительно проверяет срок сеанса; клиентское время не используется для дат статистики. Это сеансы браузерных вкладок, а не количество уникальных людей.
- Визит относится к московской дате его начала; просмотры — к датам самих просмотров. Поэтому продолжающийся после полуночи визит может дать просмотры без нового визита в этот день.
- Источник фиксируется при начале визита: допустимый `utm_source`, иначе hostname внешнего реферера, иначе прямой переход. Остальные UTM-параметры, поисковые запросы, query string и fragment страницы не передаются в статистику.
- Админка, неизвестные страницы, API, файлы и просмотры администратора с действующей сессией не учитываются. Фильтруются известные ботские User-Agent, DNT и Global Privacy Control. Полностью отличить человека от программы этот счётчик не обещает.
- Контакты заявителей, IP, полный User-Agent и полный URL реферера не записываются в аналитические таблицы. Токен визита сохраняется на сервере только в виде SHA-256. Новые cookies и внешние сервисы аналитики не добавляются. Существующий ограничитель запросов использует временный хеш IP, как и другие API проекта.
- Данные посещаемости хранятся 90 дней; старые события и сеансы удаляются при приёме следующего просмотра. История заявок этим удалением не затрагивается. При полном запрете браузерного хранилища сохранение сеанса между открытиями невозможно, поэтому число визитов может быть завышено.

Сбор начинается после установки этой версии. Прошлые посещения не восстанавливаются. JavaScript, сетевые блокировки и настройки приватности влияют на полноту статистики. Для проверки откройте сайт в отдельном приватном окне без входа в админку, затем обновите статистику в основном окне.

## API и хранение

`POST /api/analytics/pageview` принимает только небольшой JSON с идентификаторами события и сеанса, путём страницы и необязательными источниками. Нужен совпадающий Origin; лимит тела — 2 КБ, частоты — 120 событий в минуту на IP. Путь повторно проверяется на сервере по существующим публичным маршрутам. Неизвестные события не превращаются в произвольные строки отчёта.

`GET /api/admin/statistics?days=30` требует действующую административную сессию, принимает только периоды 7/30/90, возвращается с `no-store` и `noindex`. Ответ содержит агрегаты без содержимого заявок.

Миграция 4 → 5 добавляет `analytics_visits` и `analytics_pageviews` в ту же SQLite-базу, не меняя сохранённые заявки, файлы, статьи и учётные данные. Запись визита и просмотра выполняется в одной транзакции. Аналитика входит в проверяемые backup/verify/restore; старые копии схем 3 и 4 по-прежнему поддерживаются.

## Порядок установки

1. Локально выполнить `npm run check` и проверить экран админки.
2. Загрузить ветку на GitHub, дождаться Quality Gate на Linux и Windows, затем выполнить merge.
3. Перед обновлением VPS создать проверенную копию работающей базы командой `/bin/sh scripts/backup-docker.sh` из корня проекта.
4. Обновить код и пересобрать контейнер штатной командой `docker compose up -d --build --wait --wait-timeout 120`.
5. Проверить `/healthz`, вход, историю заявок и отдельный приватный визит.

При откате старая версия приложения со схемой 4 не откроет базу схемы 5. Восстанавливайте проверенную копию в новый каталог по `DATABASE-RECOVERY.md`; не удаляйте рабочий volume и не заменяйте базу поверх новых заявок.
