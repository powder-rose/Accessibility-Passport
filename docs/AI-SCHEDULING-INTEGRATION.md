# Совместная версия ИИ-помощника и расписания

Ветка `codex/ai-assistant` развивалась отдельно от `main` с расписанием. Общая версия сохраняет ИИ-помощника, генерацию текста из трёх блоков, серверное хранение материалов, описательные имена WebP, отложенную публикацию и закреплённую панель редактора. Подготовка текста и перенос метаданных из помощника сами по себе не меняют статус и время публикации. Настройки публикации и сохранение блокируются на время применения изображения.

## Совместимость базы

Две ветки использовали один номер схемы 6 для разных структур. Одного сравнения `user_version` недостаточно: миграция проверяет наличие `ai_materials` и `articles.scheduled_at` до изменения базы.

| Исходная схема      | Структура                                   | Переход на 8                                         |
| ------------------- | ------------------------------------------- | ---------------------------------------------------- |
| 3–5                 | Общие данные без материалов ИИ и расписания | Завершить прежние миграции, добавить обе возможности |
| 6, ветка расписания | `scheduled_at` и индекс, без `ai_materials` | Сохранить очередь, добавить материалы ИИ             |
| 6, ветка ИИ         | `ai_materials`, без `scheduled_at`          | Сохранить материалы, добавить расписание             |
| 7, ветка ИИ         | Материалы ИИ и поддержка описательных URL   | Сохранить материалы и URL, добавить расписание       |
| 8                   | Обе возможности                             | Повторная миграция не нужна                          |

Объединяющий переход выполняется одной транзакцией. Ошибка DDL откатывает новые структуры и маркер версии; конструктор закрывает соединение и сохраняет исходную ошибку. Неизвестные будущие номера и несогласованные исторические структуры отклоняются. Понижать `user_version` вручную нельзя.

Backup/verify/restore поддерживают оба варианта 6, AI-схему 7 и общую схему 8. Наличие материалов определяется по проверенной структуре, поэтому копия из ветки расписания не требует несуществующей таблицы ИИ. Копия и восстановление не мигрируют исходную базу; переход выполняется при открытии восстановленной базы новым приложением. Администраторские сессии по прежнему правилу исключаются из копии.

## Порядок обновления

1. Сохранить незакоммиченные серверные исходники вне репозитория. В общей версии использован экспорт четырёх файлов от коммита `47bcdf9`; исходный архив не содержит `.env` и БД.
2. Применить общую ветку в локальном репозитории, выполнить `npm ci` и `npm run check`, отправить её на GitHub и объединить после Quality Gate на Linux и Windows.
3. На VPS сохранить проверенную копию текущей базы совместимым инструментом, серверный `.env`, зашифрованный `ai-settings.enc` и прежний образ. Сохранить текущий Git-коммит и незакоммиченные изменения отдельно. Дождаться завершения платных генераций перед перезапуском: незавершённая генерация изображения после рестарта получает неизвестный результат и автоматически не повторяется.
4. Собрать и запустить объединённый коммит с тем же постоянным томом и прежним окружением. Структура 7 обновится до 8 при старте. Приложение публикует подошедшие расписания при запуске и затем каждые 15 секунд.
5. Проверить healthcheck, схему 8, вход в админку, сохранённые материалы ИИ, прежнюю статью и изображение. В редакторе должны быть одновременно ИИ-помощник и блок «Публикация» с вариантом «По расписанию».

Откат образа отдельно от базы после перехода на 8 несовместим со старыми версиями. Восстановление выполняется в новый каталог из согласованной копии по [DATABASE-RECOVERY.md](DATABASE-RECOVERY.md). `.env`, `ai-settings.enc` и временные задачи генерации не входят в SQLite-копию; рабочий том при обычной выкладке сохраняется.

## Проверки

Тесты создают исторические базы по реальным DDL обеих веток, а затем проверяют прямой переход и backup/restore, сохранность заявок, SEO, ревизий, URL, байтов изображений, общих материалов и фото ИИ. Сохранённое расписание остаётся закрытым и срабатывает один раз; старый идентификатор запроса не создаёт дубликат после обновления. Отдельно проверяются атомарный откат при конфликте индекса и отказ от неоднозначной схемы 6 без изменения данных.
