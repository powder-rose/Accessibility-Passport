# Чтение изображений статей

Точечный рефакторинг закрывает T7 технического аудита: прежде обработчик выбирал BLOB до проверки `If-None-Match`, а HEAD строил полное тело, которое затем отбрасывал Express. Теперь решение о передаче тела отделено от чтения содержимого.

## Границы кода

- `server/articles/api.ts` регистрирует прежние маршруты CRUD и `/media/articles/{uuid}.webp`; выдача изображения находится в `image-response.ts`.
- `ArticleRepository.imageMetadata()` одним SQL-запросом получает `size`, `sha256` и наличие ссылки из опубликованной неудалённой статьи. Запрос не выбирает `bytes`. Прежний отдельный `imageIsPublished()` заменён этой проекцией.
- `ArticleRepository.image()` остаётся чтением содержимого для GET и существующих проверок хранения. Успешный полный GET выполняет два запроса к изображениям: метаданные со статусом доступа и BLOB; раньше — опубликованность и BLOB. Число запросов для обычного публичного GET не увеличивается.
- HTTP-обработчик сначала проверяет существование и доступ, затем валидатор, затем HEAD, и только после этого читает байты.
- Адаптер `server/api/router.ts` отправляет ответ HEAD без тела, если обработчик уже вернул bodyless Response. Он сохраняет заданный размер, а не пересчитывает его по пустому буферу. Небольшие JSON-ответы ошибок проходят прежний путь Express.

Публичная ветка не делает асинхронных пауз между чтением метаданных и подготовкой ответа. Межзапросный кеш опубликованности не добавляется: каждый запрос заново проверяет состояние статьи. Текущая модель одного экземпляра приложения с SQLite сохраняется.

## HTTP-контракт

| Запрос                                           | Ответ                                             | Загрузка BLOB в JavaScript |
| ------------------------------------------------ | ------------------------------------------------- | -------------------------- |
| Обычный разрешённый GET                          | 200, исходные WebP-байты                          | Один раз                   |
| Разрешённый HEAD                                 | 200, без тела; `Content-Length` равен размеру GET | Нет                        |
| Разрешённая перепроверка с совпавшим валидатором | 304, без тела                                     | Нет                        |
| GET с устаревшим валидатором                     | 200, исходные байты                               | Один раз                   |
| Черновое изображение без действующей сессии      | 404, `no-store`                                   | Нет                        |
| Несуществующее изображение                       | 404, `no-store`                                   | Нет                        |

ETag по-прежнему равен SHA-256 изображения в кавычках. Для публичных файлов сохраняется `public, max-age=0, must-revalidate`, для доступных сотруднику непубличных — `private, no-store`. `image/webp` и `nosniff` сохраняются. У 304 Express удаляет заголовки тела; HEAD 200 сохраняет тип и длину представления. Проверка опубликованности/сессии выполняется до выдачи любого 304: известный ETag или `If-None-Match: *` не открывает черновик.

Условная выдача учитывает сильный ETag, слабый `W/`, список валидаторов и `*`. Это перенос прежней проверки Express перед загрузкой тела, а не универсальный HTTP-парсер. Сравниваются сгенерированные сервером SHA-256 ETag. Сохранена прежняя особенность reload: точное совпадение публичного ETag даёт 304 и при `Cache-Control: no-cache`; прочие валидаторы при таком заголовке проходят как полный ответ. Авторизованный приватный reload с `no-cache` остаётся 200. Изменение этой политики не входит в рефакторинг.

Правила HEAD, `Content-Length` и `If-None-Match`: [RFC 9110, HEAD](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.3.2), [Content-Length](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.6), [If-None-Match](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.2).

## Проверки и пределы

`tests/article-image-reads.test.ts` проверяет SQL-проекцию через SQLite view, у которой обращение к столбцу bytes вызывает ошибку: метаданные читаются успешно, а чтение содержимого действительно достигает этого столбца. HTTP-тесты считают фактические вызовы чтения BLOB и загруженные байты; используют настоящий WebP, проверяют тело GET, длину HEAD, 304, устаревшие валидаторы, reload, авторизацию и отзыв сессии, обложку/встроенное изображение, несколько ссылок, снятие публикации и мягкое удаление.

В отдельном локальном сравнении до/после на синтетическом BLOB в 750 220 байт совпали статус, длина ответа, тип и политика кеширования в 26 сценариях. В HEAD и 304 загрузка содержимого уменьшилась с 750 220 до 0 байт; обычный GET сохранил одно чтение всех байтов. Это счётчик материализованных данных, не замер ускорения, физического дискового I/O, пропускной способности VPS или поведения CDN. SQLite может читать страницы базы для поиска метаданных.

Схема базы, загрузка/кодирование изображений, квоты, очистка, URL, интерфейс и SEO не меняются. Новых зависимостей, фоновых процессов и миграций нет. Внешняя инфраструктура может иметь собственное кеширование; её настройки проверяются отдельно при размещении.
