# Чтение статей, навигация и sitemap

HTTP-списки и серверные страницы используют отдельный `ArticleQueries`. Полные записи читаются для одной статьи и операций редактирования; список не загружает тексты в JavaScript и не вызывает их HTML-санитайзер.

| Назначение        | Данные                                                     |
| ----------------- | ---------------------------------------------------------- |
| Sitemap           | Только актуальные slug опубликованных, не удалённых статей |
| Существующий блог | До 12 кратких карточек, количество результатов и категории |
| Страница статьи   | Один очищенный текст и до трёх кратких связанных карточек  |
| Список админки    | До 25 кратких карточек с revision, количество и категории  |
| Категории         | DISTINCT по отдельному столбцу без разбора payload         |

Без фильтра запрос сначала выбирает ограниченный набор ID, затем извлекает поля карточек. SQLite использует `json_extract` для метаданных из существующего payload; внутри SQLite JSON всё ещё может разбираться. Это не обещание нулевого чтения страниц базы. В Node.js не передаются полные тексты и не выполняется их повторная очистка ради карточек. Глобальный поиск по заголовку/описанию или категории остаётся линейным; полнотекстовый индекс и изменение схемы этим исправлением не вводятся.

Очистка HTML при записи, чтении полной статьи и предпросмотре сохраняется, включая ранее сохранённый HTML. `ArticleRepository.list()` оставлен для совместимости служебного доступа к полным записям; HTTP/SSR его не используют.

## Существующий блог

Навигация использует тот же `/blog/` с параметрами `page`, `category`, `q`. Новые коммерческие страницы и разделы не создаются. Адреса статей, услуг и редиректы старых slug сохраняются.

- На экране до 12 карточек. Ссылки «Назад»/«Далее» присутствуют в серверном HTML и работают без JavaScript.
- Поиск отправляется кнопкой «Найти» или Enter и ищет заголовок/SEO-описание среди всех опубликованных статей. Категория также применяется ко всему каталогу, затем начинается первая порция.
- Кириллица обрабатывается регистронезависимо тем же JavaScript-преобразованием `toLocaleLowerCase('ru')`, зарегистрированным как SQL-функция. Символы `%` и `_` означают обычные символы, не SQL-шаблоны.
- Порядок сохраняется: дата публикации/создания по убыванию, ID при совпадении дат. Связанные материалы сначала выбираются из той же категории, затем по этому порядку.
- Некорректные параметры дают 400; несуществующий номер порции — 404. Пустой результат допустимого поиска — 200 с сообщением об отсутствии совпадений.

Параметры нормализуются: `page` — положительное целое до 999999, поисковая строка — до 100 символов, категория — до 80. Повторяющиеся основные параметры отклоняются. UTM не включаются в canonical или ссылки навигации.

## Индексация

У каждой обычной порции собственный canonical: первая — `/blog/`, следующая — `/blog/?page=2` и далее. У вариантов с поиском/категорией — `noindex, follow`, нормализованный собственный URL и обычные ссылки на статьи. Список schema.org содержит только отображаемые карточки. Sitemap продолжает включать все опубликованные статьи независимо от текущей порции.

Robots.txt разрешает обход публичных URL с параметрами, чтобы робот мог прочитать canonical пагинации и noindex поиска/категорий. Общий запрет query и прежнее точечное исключение `/blog/?` удалены; префиксы админки/API остаются закрытыми. Политика всех параметров: [ROBOTS-PARAMETERS.md](ROBOTS-PARAMETERS.md). Основание для навигации: [Google Search Central о навигации списков](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading).

## Админка

API `/api/admin/articles` сохраняет прежнюю авторизацию и no-store, теперь возвращает краткие карточки и параметры порции. Доступны `page`, `status=all|draft|published`, `q`, `category`. Поиск заголовка/категории выполняется по всему доступному списку после паузы ввода 300 мс; переход по статусу/поиску начинает первую порцию. Предыдущий запрос отменяется, устаревший ответ не подменяет новый. Таймауты из `docs/ADMIN-REQUESTS.md` сохраняются.

Если после удаления последней записи последней порции номер оказался за границей, сервер возвращает последнюю существующую порцию. Ошибка чтения сохраняет последний загруженный список с явным сообщением и кнопкой повтора.

Изменение категории сначала читает полную запись только выбранной статьи. Если её revision уже отличается от списка, запись блокируется до обновления списка. Между чтением и сохранением действует прежняя серверная проверка revision. Текст, изображения и чужие изменения не заменяются пустыми значениями из краткой карточки; автоматических повторов записи нет. Редактор читает полный текст отдельным запросом как раньше.

## Проверки и ограничения

Регрессионные тесты проверяют ограничение выдачи, доступность всех записей при одинаковых датах, поиск кириллицы за первой порцией, категории, буквальные `%`/`_`, изоляцию черновиков/удалённых статей, лимит связанных записей, авторизацию, revision и сохранение текста при смене категории. HTTP-проверки подтверждают серверные ссылки, canonical, noindex фильтров, 400/404, состав page-data и sitemap без чтения payload. Схема SQLite остаётся 4; существующие копии и процедуры восстановления совместимы.

Локальные замеры на искусственных данных показывают стоимость конкретных запросов, не производственную ёмкость VPS. Подсчёт результатов, глубокие OFFSET, глобальный поиск и список категорий зависят от размера каталога. При существенно большем объёме нужны новые измерения, а не вывод о бесконечном масштабировании.
