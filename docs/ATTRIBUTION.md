# Сохранение UTM между страницами

## Поведение

Используется последний непустой набор UTM в сессии текущей вкладки. Пример:

1. Посетитель открывает `/?utm_source=yandex&utm_medium=cpc&utm_campaign=osi`.
2. При запуске публичной страницы метки сохраняются до гидратации React.
3. Посетитель переходит на `/anketa-osi/`, затем к форме или квизу.
4. Заявка и события получают исходные UTM, хотя в текущем адресе их уже нет.

Сохраняются только `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`. Каждое значение ограничено 300 символами, как и в серверной схеме приёма заявки. Сохраняемый объект не содержит адрес страницы, hash, телефон, email, файлы и другие query-параметры. Содержимое самих UTM задаёт рекламная ссылка: не включайте в них персональные данные.

## Правила замены

- Адрес без непустых UTM сохраняет прежний источник. Параметры `service` и `object_type` не сбрасывают источник.
- Новый адрес хотя бы с одной непустой UTM целиком заменяет прежний набор. Например, новый `utm_source=email` не наследует старые `utm_campaign` и `utm_term`.
- Пустые UTM не добавляются в набор. Дублирующиеся параметры читаются как прежде: используется первое значение.
- Внутренние ссылки, canonical, sitemap и URL после перехода не переписываются.
- Общая функция `attribution()` используется и формами, и событиями. Значение `pageUrl` заявки остаётся фактическим адресом текущей страницы.
- Начальная фиксация работает независимо от заполнения ID Метрики. Административные страницы не фиксируют рекламный источник при загрузке.

## Хранение и ограничения

Ключ sessionStorage: `osi-utm-attribution-v1`. Не используются localStorage, новые cookie, серверные сессии или зависимости. Хранилище ограничено origin и сессией вкладки; это выбранная модель сайта, а не точное воспроизведение сессий конкретной рекламной системы.

При недоступном sessionStorage формы и события продолжают работать с метками из текущего URL. Сохранение источника после полной навигации в таком браузере не гарантируется. Повреждённый или слишком большой сохранённый объект игнорируется; из него читаются только допустимые строковые поля. При ошибке записи выполняется попытка удалить старый набор, чтобы не подставить предыдущую кампанию.

При SSR функция возвращает пустой объект и не обращается к browser API. Чтение клиентского хранилища не меняет серверный HTML.

## Проверка

Автотесты `tests/attribution.test.ts` проверяют перенос между страницами, полную замену кампании, ограничения значений, исключение лишних полей, повреждённое/недоступное хранилище, SSR, события и сохранение контактной/quiz-заявки через реальный API в SQLite.

Ручной сценарий: открыть главную с синтетическими UTM, перейти по ссылке на анкету и отправить тестовую заявку. В сохранённой заявке должны быть исходные метки и актуальный `sourcePage`. Для проверки используйте локальную тестовую базу, а не данные реальных клиентов.
