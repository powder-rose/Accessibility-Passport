## Quality Gate

```text
format:check → lint → audit:check → build → test
```

`npm run audit:check` запускает полный `npm audit --json --audit-level=high` для production- и dev-зависимостей и проверяет результат вместе с lockfile. High и critical останавливают `npm run check`, кроме одного временного исключения ниже. Количества предупреждений всех уровней остаются видимыми в отчёте. Workflow Linux/Windows использует эту же команду.

Проверка обращается к npm registry. Для сетевого запроса задан таймаут 20 секунд и один повтор. Недоступность registry или другая ошибка npm останавливает gate; успешный результат не подставляется автоматически. Audit не устанавливает обновления.

Дополнительная проверка только production-зависимостей:

```powershell
npm audit --omit=dev
```

На 9 ноября этот отдельный production-аудит завершился успешно: 0 известных предупреждений всех уровней.

## Временное исключение для picomatch

18 ноября оба задания Quality Gate остановились до сборки и тестов: полный audit показывает 6 high и 8 moderate. Все high связаны с GHSA-fc5q-39xc-vjpf, добавленной в проверенную базу GitHub 17 ноября. Отложенная публикация и закреплённая панель редактора не являются причиной отказа.

Advisory описывает ReDoS при передаче специально составленного glob-шаблона в picomatch. На момент проверки последняя опубликованная версия — 4.0.7; исправленной версии нет. `npm audit fix --force` предлагает откат Vite на 6.2.7, а не исправление текущего picomatch. Такой откат не применяется.

В этом приложении picomatch используется Vite, tinyglobby и lint-инструментами. Glob-шаблоны задаются исходниками и конфигурацией проекта; HTTP API не принимает glob-шаблоны посетителей для обработки этими пакетами. Dev server предназначен для локальной разработки. Docker runtime устанавливает пакеты через `npm ci --omit=dev`; dev-сервер и lint-инструменты в нём не запускаются. Это обоснование исключения для данного проекта, а не утверждение об исправлении библиотеки. Нельзя использовать эту оценку для сборки недоверенных проектов или публично доступного dev server.

Исключение ограничено следующими пакетами и версиями в корневом `node_modules`:

| Пакет                                  | Версия   |
| -------------------------------------- | -------- |
| `picomatch`                            | `4.0.7`  |
| `fdir`                                 | `6.5.0`  |
| `tinyglobby`                           | `0.2.17` |
| `vite`                                 | `8.3.6`  |
| `@vitejs/plugin-react`                 | `6.0.2`  |
| `@typescript-eslint/typescript-estree` | `8.72.1` |

Каждый затронутый узел цепочки должен иметь `dev: true` в package-lock.json. Скрипт рекурсивно проверяет причины предупреждений, точный advisory, severity и диапазон `<=4.0.7`. Новая high/critical, переход зависимости в production, изменение версии, неизвестная цепочка или неполный ответ npm останавливают gate. Умеренные предупреждения сохраняют прежний неблокирующий порог.

В журнал выводятся `AUDIT_COUNTS`, `AUDIT_TEMPORARY_EXCEPTION` с advisory и сроком, а также `AUDIT_REVIEWED_PACKAGES`. Поэтому `AUDIT_POLICY_OK` означает прохождение описанной политики, а не отсутствие уязвимостей. Обычный `npm audit` продолжает показывать исходные предупреждения.

Срок исключения заканчивается 2 декабря 2026 года в 00:00 UTC (03:00 МСК). После этого оно автоматически перестаёт пропускать затронутые зависимости. До этой даты нужно проверить upstream и npm registry, установить исправленную версию, удалить исключение из `scripts/lib/dependency-audit.mjs` и повторить полный gate. Продление без новой оценки не предусмотрено. Проверки политики покрывают production-узлы, новые advisory, критический уровень, смену версии, истечение срока, циклы, ошибки registry и неполные ответы.

## Результат проверки 9 ноября

До изменения полный audit показывал 12 затронутых пакетов: 2 high и 10 moderate. После изменения high/critical отсутствуют; остаются 10 moderate, связанные с одной причиной — `minimatch@10.2.6`, GHSA-g3hv-75wg-m249. Число затронутых пакетов не равно числу независимых уязвимостей.

`eslint@10.14.0`, `@eslint/config-array@0.23.5` и `@typescript-eslint/typescript-estree@8.72.1` используют minimatch 10.x. Исправление advisory находится в 11.0.1 и не входит в их текущие диапазоны. На дату проверки версии верхнего уровня уже последние стабильные. Остаётся дождаться совместимого обновления родителей либо отдельно проверить смену lint toolchain.

В этом проекте цепочка относится к dev-инструментам, а glob-шаблоны заданы конфигурацией репозитория. По коду публичного HTTP API эти инструменты не используются. Это ограничивает доступность сценария через сайт, но не отменяет предупреждение зависимости. Оно не скрыто из npm audit и не объявлено исправленным.

Отсутствие предупреждений high/critical относится к результату npm audit на указанную дату и не доказывает отсутствие всех возможных уязвимостей проекта.

## Проверки совместимости

Полный gate сохраняет все прежние тесты: SSR/SEO, формы и UTM, идемпотентность, закрытые вложения, статьи, пагинацию и dev server. Добавлены две проверки: раннее отклонение большой коллекции без накопления ошибок элементов и отказ HTTP API от некорректных словарей UTM/ответов без сохранения заявки.

Данные SQLite, содержимое статей, пользовательские контакты, секреты и схема базы этим обновлением не переписываются. После применения патча зависимости переустанавливаются через `npm ci`, затем выполняется `npm run check`.
