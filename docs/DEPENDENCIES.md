Версии закреплены точно, lockfile сформирован npm. Vite остаётся dev-зависимостью, Zod — production-зависимостью. Обновление не использует `npm audit fix --force` или overrides.

Для Zod 4 в трёх `z.record` явно задана схема строкового ключа: UTM, ответы квиза и секции контента. Проверки значений, whitelist UTM, обязательные вопросы, ограничения коллекций, контактов и согласия сохраняются.

Изменение upstream для Zod отклоняет слишком большие ограниченные коллекции до обхода элементов. Это не универсальная защита от любых больших входных данных: ограничения тела HTTP и размеров коллекций по-прежнему нужны.

## Quality Gate

```text
format:check → lint → audit:check → build → test
```

`npm run audit:check` проверяет полный набор production- и dev-зависимостей. High и critical дают неуспешный exit-код и останавливают `npm run check`, в том числе в существующем workflow Linux/Windows. Умеренные уровни остаются видимыми в отчёте.

Проверка обращается к npm registry. Для сетевого запроса задан таймаут 20 секунд и один повтор. Недоступность registry или другая ошибка npm останавливает gate; успешный результат не подставляется автоматически. Audit не устанавливает обновления.

Дополнительная проверка только production-зависимостей:

```powershell
npm audit --omit=dev
```

На дату проверки этот отдельный production-аудит завершился успешно: 0 известных предупреждений всех уровней.

## Остаточные предупреждения

До изменения полный audit показывал 12 затронутых пакетов: 2 high и 10 moderate. После изменения high/critical отсутствуют; остаются 10 moderate, связанные с одной причиной — `minimatch@10.2.6`, GHSA-g3hv-75wg-m249. Число затронутых пакетов не равно числу независимых уязвимостей.

`eslint@10.14.0`, `@eslint/config-array@0.23.5` и `@typescript-eslint/typescript-estree@8.72.1` используют minimatch 10.x. Исправление advisory находится в 11.0.1 и не входит в их текущие диапазоны. На дату проверки версии верхнего уровня уже последние стабильные. Остаётся дождаться совместимого обновления родителей либо отдельно проверить смену lint toolchain.

В этом проекте цепочка относится к dev-инструментам, а glob-шаблоны заданы конфигурацией репозитория. По коду публичного HTTP API эти инструменты не используются. Это ограничивает доступность сценария через сайт, но не отменяет предупреждение зависимости. Оно не скрыто из npm audit и не объявлено исправленным.

Отсутствие предупреждений high/critical относится к результату npm audit на указанную дату и не доказывает отсутствие всех возможных уязвимостей проекта.

## Проверки совместимости

Полный gate сохраняет все прежние тесты: SSR/SEO, формы и UTM, идемпотентность, закрытые вложения, статьи, пагинацию и dev server. Добавлены две проверки: раннее отклонение большой коллекции без накопления ошибок элементов и отказ HTTP API от некорректных словарей UTM/ответов без сохранения заявки.

Данные SQLite, содержимое статей, пользовательские контакты, секреты и схема базы этим обновлением не переписываются. После применения патча зависимости переустанавливаются через `npm ci`, затем выполняется `npm run check`.
