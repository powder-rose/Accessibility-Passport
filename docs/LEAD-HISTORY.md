# История заявок

## Работа в админке

После входа в `/admin/` список показывает по 25 заявок. «Далее» открывает более старые записи, «Назад» возвращает к предыдущей странице. Номер относится к текущему просмотру: прямого перехода к произвольной странице нет.

«Обновить список» возвращает к первой странице с новыми заявками. Общее количество учитывает всю базу, а не только открытую страницу. Новые заявки появляются после загрузки страницы списка; автоматических уведомлений и фонового опроса пока нет.

На время загрузки кнопки отключены. Ошибка запроса сохраняет уже показанную страницу. «Повторить загрузку» повторяет именно неудавшийся запрос: например, переход на следующую страницу. При ответе 401/403 список закрывается и появляется форма повторного входа. Пустая база показывает «Заявок пока нет.».

Вложения доступны через прежние защищённые ссылки. Публичные страницы и формы заявок не меняются.

## API и порядок записей

`GET /api/admin/leads` требует действующую администраторскую сессию и возвращает:

```json
{
  "leads": [],
  "total": 0,
  "nextCursor": null
}
```

Массив `leads` и структура записи сохранены. Без параметров размер страницы остаётся 100 для совместимости; админка явно запрашивает `limit=25`.

- `limit`: целое число от 1 до 100.
- `cursor`: непрозрачное значение `nextCursor` из предыдущего ответа. `null` означает конец истории. Не собирайте cursor вручную.
- Повторяющиеся параметры `limit`/`cursor`, некорректные размеры и повреждённые курсоры получают 400.
- Отсутствующая или истёкшая сессия получает 401 до проверки параметров. Метаданные истории без авторизации не выдаются.
- Ответы имеют `Cache-Control: no-store`.

Порядок: `created_at DESC, id DESC`. Вторая часть устраняет неоднозначность при одинаковом времени записи. Запрос следующей страницы использует последнюю пару «дата + ID», а не смещение OFFSET: новые заявки перед границей не сдвигают уже просматриваемую историю. Параметры передаются в SQL через placeholders.

Курсор не содержит контактов, но не является секретом или заменой сессии. Он кодируется, а не шифруется. Общий счётчик отражает состояние базы на момент запроса; история не является неизменяемым снимком между запросами.

## Сохранность и границы патча

Миграция схемы не требуется. База, заявки, статусы, содержимое payload и вложения не переписываются. `Store.listLeads()` сохраняет прежний контракт массива до 100 записей для внутренних вызовов; администраторский API использует новый постраничный метод.

Этот этап закрывает ограничение доступности истории. Поиск, редактирование статусов, экспорт и доставка уведомлений остаются отдельными задачами. Замечание аудита A02 пока закрыто частично.

## Ручная проверка на тестовой базе

1. Сохранить более 100 синтетических заявок, в том числе с одинаковой датой.
2. Войти, пройти до последней страницы и убедиться, что самая старая заявка доступна без дублей.
3. Проверить «Назад», «Обновить список», пустую базу, ошибку загрузки и повторный вход при истёкшей сессии.
4. Открыть вложение из старой заявки с действующей сессией; без сессии доступ должен быть закрыт.
5. На узком экране проверить перенос кнопок и управление с клавиатуры.

Автоматические регрессии находятся в `tests/lead-pagination.test.ts` и запускаются общим `npm run check`.
