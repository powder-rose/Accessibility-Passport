# Robots.txt и параметры URL

Robots.txt формируется сервером из `server/seo.ts`. Общий запрет `Disallow: /*?*` мешал обходить рекламные ссылки и читать их canonical; исключение `Allow: /blog/?` охватывало только список блога. Теперь публичные URL доступны для обхода независимо от наличия, порядка и кодирования параметров.

```text
User-agent: *
Allow: /
Disallow: /admin
Disallow: /api

Sitemap: https://pasport-dostupnosty.ru/sitemap.xml
```

Адрес sitemap берётся из проверенного `site.domain`. Правила `/admin` и `/api` — запреты префиксов: они охватывают адрес без слеша, вложенные пути и query, например `/api?utm_source=qa` и `/admin/articles/new/?fresh=1`. Исключений по UTM поверх этих запретов нет. Публичные CSS, JS, шрифты и изображения статей доступны для обхода.

## Политика публичных параметров

| URL или параметры                                                                                | Обход    | Canonical и индексация                                                               |
| ------------------------------------------------------------------------------------------------ | -------- | ------------------------------------------------------------------------------------ |
| Главная и страницы услуг с `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content` | Разрешён | Основной адрес страницы без query; `index, follow`                                   |
| Главная и услуги с `service`, `object_type`, в том числе вместе с UTM                            | Разрешён | Основной адрес страницы без query; выбор в форме сохраняется                         |
| `/blog/`, `?page=1`                                                                              | Разрешён | `/blog/`; непустой список без поиска/категории — `index, follow`                     |
| `/blog/?page=2` и следующие существующие страницы                                                | Разрешён | Собственный адрес с `page`; UTM и посторонние параметры исключены                    |
| `/blog/?q=…`, `?category=…`, их сочетания с `page`                                               | Разрешён | `noindex, follow`; собственный нормализованный URL с действующими параметрами списка |
| Пустой результат поиска или пустой блог                                                          | Разрешён | `noindex, follow`                                                                    |
| `/blog/slug/?utm_source=…`                                                                       | Разрешён | Адрес опубликованной статьи без query; `index, follow`                               |
| Неизвестные параметры публичной страницы                                                         | Разрешён | Игнорируются маршрутом и не входят в canonical                                       |
| Юридические страницы с query                                                                     | Разрешён | Прежний `noindex, nofollow`; canonical без query                                     |
| Некорректные параметры блога, несуществующая страница/статья                                     | Разрешён | Настоящие 400/404 и `noindex, nofollow` доступны роботу                              |

`service` и `object_type` выбирают значения формы, а не создают отдельные страницы услуг. Неизвестное значение не подставляется как допустимый выбор. Поля `page`, `q` и `category` изменяют состав списка, поэтому их нельзя удалять из canonical как рекламные метки. Неизвестные параметры не создают новые варианты списка или ссылки пагинации.

Патч меняет правила обхода; существующая серверная логика canonical, noindex, формы и фильтров сохраняется и проверяется HTTP-тестами. Новых страниц, редиректов для удаления UTM, параметров конфигурации и зависимостей нет. Перенаправления на завершающий слеш и актуальный slug сохраняют query для атрибуции. В sitemap остаются только основные публичные адреса и опубликованные статьи без query; все страницы пагинации доступны по обычным HTML-ссылкам.

## Почему здесь нет общего запрета query

Robots.txt управляет обходом, а не выбором основного URL. Если запретить дубли с UTM, робот не сможет прочитать их canonical. Аналогично, noindex поиска требует доступа к ответу страницы. Это соответствует документации Google: [канонизация](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls), [noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing), [правила robots.txt](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec).

Дополнительный `Clean-param` не вводится: текущая политика использует серверные canonical и noindex и не требует отдельного набора правил для каждого поисковика. Открытый обход не гарантирует индексацию или выбор заданного canonical. При появлении новых параметров, которые действительно меняют содержимое, нужно определить их canonical/noindex и ссылки навигации до публикации.

Запреты robots.txt не заменяют авторизацию: API админки и закрытые вложения по-прежнему проверяют доступ на сервере. HTTP-заголовки API `no-store` и `X-Robots-Tag: noindex, nofollow` сохраняются. Публичные изображения опубликованных статей нельзя закрывать общим запретом `/media`; доступность черновых изображений регулирует сервер.

## Проверка

`npm run check` собирает production-версию и запускает регрессионные тесты. `tests/robots-parameters.test.ts` проверяет фактически выданный robots.txt, публичные/закрытые URL с разным порядком параметров, SSR canonical и noindex, выбор формы, пагинацию, query при редиректах, HTTP-ошибки и чистые адреса sitemap. Проверки поискового индекса и доступности production-домена в локальный тест не входят.
